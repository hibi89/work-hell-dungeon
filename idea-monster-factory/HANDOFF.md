# HANDOFF — 아이디어 괴물 공장

## 1. 목표·용도·확정 요구·기술

- 목표: `work-hell-dungeon` 저장소에 두 번째 독립 미니 앱을 별도 브랜치로 구현한다.
- 용도: 사용자의 거친 아이디어를 여러 제품 콘셉트와 실행 가능한 첫 실험으로 바꾸는 재미형 브레인스토밍 도구.
- 확정 요구: 업무 던전 앱을 보존하고, 아이디어 괴물 공장은 별도 디렉터리에 둔다. 간단한 이름 뽑기에서 끝내지 않고 제품 구상에 쓸 결과를 제공한다.
- 기술: 의존성 없는 단일 HTML/CSS/JavaScript. 외부 AI·API 없음.

## 2. 완료 기능·변경·결정 근거

- 로컬 규칙 기반 분야 자동 감지와 수동 선택, 결과 분위기 및 돌연변이 농도·초기 범위 조절.
- 세 성격(실전형, 엉뚱함형, 수집형)의 후보와 절차 생성으로 한 아이디어를 서로 다른 제품 방향으로 비교한다.
- 상세 설계서에 타깃, 불편, 작동 방식, 초기 기능, 30초 시연, 수익화 실험, 리스크, 사용자 검증 계획을 제공한다.
- 사용자가 직접 선택한 경우만 로컬 도감에 저장하며, 도감에서 저장 설계서를 다시 열고 개별/전체 삭제할 수 있다. 복사와 Markdown 파일 내보내기도 지원한다.
- 일기→웹툰, 상권·입지 비교, 10분 학습처럼 눈에 띄는 아이디어 문맥은 별도 규칙으로 첫 사용자·문제·초기 기능을 구체화한다.
- API 방식과 비교했을 때 비용·비밀정보·외부 전송이 없는 정적 로컬 방식을 1차안으로 선택했다. 자연어 해석이 제한된다는 점은 README에 공개한다.

## 3. 테스트 명령·성공/실패 수·검증 범위

- 정적 검증 2건 PASS: Node `vm.Script`로 임베디드 JavaScript 문법 파싱; Python `html.parser`로 HTML을 읽고 31개 정적 ID 중복이 없음을 확인.
- 브라우저 자동 스모크는 미완료. Playwright 기본 Chromium 실행 및 설치된 Chromium 경로 실행, 총 2회 시도 모두 실행 파일 부재로 브라우저가 시작되지 않음.
- 입력→후보 생성, 카드 선택, 보관·삭제, 복사·Markdown 다운로드, XSS 안전성 및 모바일 레이아웃은 미검증.
- 외부 서비스 미연결이므로 AI 결과 품질·시장 반응·수익성은 검증 범위 밖이다.

## 4. 완료·진행·대기·차단·중단 지점

- 차단/중단: 없음.

## 5. 오류 근거·원인·시도·재시도 금지·대안

- 앱 런타임 오류는 아직 관찰되지 않았으나, 실제 브라우저가 실행되지 않아 오류 부재를 확정하지 않는다.
- 브라우저 검증 실패 원인은 애플리케이션 오류가 아니라 실행 컨테이너에 Chromium 바이너리가 없는 환경 문제다. 재시도해도 동일한 파일 부재라 추가 브라우저 설치·네트워크 다운로드는 하지 않았다.
- 로컬 저장소가 비활성화되거나 용량 오류가 발생하면 도감 저장이 실패할 수 있도록 사용자 알림을 표시한다.
- 사용자의 아이디어는 생성 시 외부로 전송하지 않는다.
